1. A / B / D - Count each wave

For each wave as it breaks: pick how it broke, then tap its height. The breaker type stays picked, so most waves take one tap. The app works out ALPHA (highest 33 average), BRAVO (highest wave) and DELTA (breaker percentages).

Breaker type
  • Spilling (S): least dangerous to small boats and landing craft. Preferred for landings.
  • Plunging (P): sudden, concentrated break. Less preferred; long swell and offshore wind make it worse.
  • Surging (X): least common and most violent. It keeps its energy and runs far up the beach.

From NTTP 3-59.3M / MCRP 2-10.3, Appendix D (Surf Zone Features and the Formation of Breakers), Apr 2024. Drawing made for this app.

Wave height (ft)
  • Judge each breaker at the moment it breaks, from the trough in front of it to the crest.
  • Record to the nearest 1/2 ft. ALPHA is the average of the highest 33 of 100 waves; BRAVO is the single highest.
  • Swell and chop measured offshore are not breaker heights. NOAA buoy heights are offshore too.

    Human decision (required)

    The calculator only compares entered values with listed limits. It never makes, recommends or sends a GO / NO-GO decision. The responsible person records the decision here. If any input changes afterwards, the decision is flagged for re-confirmation.

    10. Human control and tools used

    Human control

    • Approval point: only the BPTC or SRM records GO, GO with restrictions or NO-GO in section 8. The app starts every observation as PENDING.
    • Prohibited actions (enforced in code): the app does not choose a decision or send data. A Content-Security-Policy allows only the app's own files and, when you tap Show map, map pictures from Esri (server.arcgisonline.com), and, when online, the NWS forecast for the selected beach's grid square (api.weather.gov) and, when you tap Check this copy, the official file list (wardenofthekeys.github.io). Without a connection the packaged forecast is used. Nothing typed into the app is ever sent. It asks for no names or other PII.
    • NOAA estimates: wave, wind and visibility values come from public NOAA reports. The 100-wave count built from them is an estimate, marked in the overview and the verification block. An observed surf-zone count replaces it.
    • Monitoring: input warnings, the workflow verification block, the NOAA cross-check, and a re-confirm flag whenever inputs change after a decision.
    • Escalation: any red warning, CHECK note, at-limit or exceeded craft, or any mismatch with the paper worksheet goes to the BPTC or SRM. The paper worksheet is the reference.
    • Shutdown: close the tab. Clear form erases the data saved on this device. The browser keeps an offline copy of the app's own files; clearing the site's data removes it. There are no accounts or servers.

    Tools and resources used

    • Claude Code desktop app with the Anthropic Claude Opus 5.5 model, used to write and review code.
    • A command-line shell for file checks, and the Claude Code built-in browser preview for testing.
    • No external libraries and no AI inside the app. Data: NOAA NDBC buoy, CO-OPS station and NWS airfield reports (7 days) and the NWS gridpoint forecast (5 days), packaged in conditions-data.js and refreshed about every hour. Map pictures: Esri, only when the map is opened.
    • Speaking and scanning use the phone's own dictation and text recognition (Apple, Google). The app receives only the text.
    • MSI tables were carried over unchanged from the original worksheet version. The team must cite the source worksheet or publication.
